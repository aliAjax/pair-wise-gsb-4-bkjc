# License Lens · 贡献归属台账

整理开源项目时，把“提交改过哪些文件、谁签过 CLA、最终该怎么署名”从散落的表格里收拢成一本台账。纯前端 React + TypeScript 应用（Vite），数据只保存在浏览器本地，可导出/导入 JSON 备份。

## 它解决什么

- **登记提交**：每条提交记录仓库、提交号、贡献者、文件清单及每个文件的许可条款。
- **CLA 独立签记**：贡献者档案单独维护 CLA 签署状态；名下仍有在档文件却没签 CLA 会出现在缺口里。
- **条款冲突拦截**：同一仓库、同一路径出现两种不同许可条款时自动标为冲突，**暂停进入归属声明**；在复核中心人工裁定采用哪一条后才放行。所有在档贡献者都保留署名，未采用的条款留在复核记录中可追溯。
- **改动后复核失效**：复核以快照指纹（提交号 + 文件路径 + 许可条款）锁定。提交号或文件清单一旦增删改，指纹对不上，旧复核自动标记失效、需重新复核。
- **文件撤下只撤该文件**：撤下一个文件只撤回它产生的归属；贡献者名下还有其他在档文件时署名继续保留；恢复文件后重新计入。
- **缺口重开可查**：每次打开都按当前资料重算缺口（资料不全、CLA 未签、冲突待复核、复核失效），旧状态不会掩盖新问题。
- **导出声明**：按仓库、贡献者归并生成 `NOTICE.md`，冲突未复核或已撤下的文件不会混入声明。

## 架构：资料 / 判定 / 保存分离

| 层 | 文件 | 职责 |
|---|---|---|
| 资料 | `src/types.ts` | 提交、文件声明、贡献者、复核记录的数据结构 |
| 判定 | `src/engine.ts` | 纯函数：文件聚合、指纹、冲突识别、缺口清单、可进声明的归属 |
| 输出 | `src/notice.ts` | 只消费判定结果，格式化为 Markdown 声明 |
| 保存 | `src/storage.ts` | localStorage 读写、示例资料、JSON 导入导出 |
| 界面 | `src/App.tsx` | 缺口概览 / 提交记录 / 贡献者·CLA / 复核中心 / 归属声明 |

判定层不读写存储、不依赖 React，可单独测试或替换存储实现。

## 运行

```bash
npm install
npm run dev      # 本地开发
npm run build    # 类型检查 + 构建
```
