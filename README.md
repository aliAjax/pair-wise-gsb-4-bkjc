# License Lens · 贡献归属台账

纯前端工具，用于整理开源项目的贡献归属：谁在哪个仓库、哪个提交改了哪些文件、适用什么许可条款、谁签过 CLA，汇总成可导出的归属声明（NOTICE）。

## 解决的问题

- 提交记录和 CLA 签署情况散在各处表格，归属声明容易漏人；
- 同一文件在不同提交中出现**不一致的许可条款**时，必须停下复核，不能直接进声明；
- 文件撤下后，只能撤回**该文件**产生的归属，贡献者在其它文件上的归属保留；
- 复核之后若**提交号或文件清单**被改动，原复核自动失效，需要重新确认；
- 关掉重开后，所有待处理缺口仍可追查。

## 台账结构（资料 / 判定 / 保存三层分离）

| 层 | 文件 | 内容 |
|---|---|---|
| 资料层 | `src/types.ts`、「提交登记」「贡献者 / CLA」页 | 只记录事实：仓库、提交号、贡献者（含 CLA 状态）、文件清单与条款、撤下标记 |
| 判定层 | `src/engine.ts`、「冲突复核」页 | 纯函数推导：条款冲突、复核是否失效、缺口清单、最终归属与声明；人工复核结论单独保存 |
| 保存层 | `src/storage.ts` | 只负责 localStorage 读写（资料与判定两个键）及 JSON 备份导入导出，不含任何业务规则 |

重开应用时，判定结果全部由资料 + 已保存的复核重新推导，缺口不会丢、也不会残留过期结论。

### 判定规则要点

1. 同仓库同路径的文件跨提交聚合：登记条款多于一种 → **冲突，停待复核**，文件不进声明；
2. 冲突文件在「冲突复核」页选定采用条款（须仍是登记条款之一）后才解除停留；
3. 复核记录保存资料指纹（提交号 + 文件清单），任一改动 → 复核标记失效，重新复核；
4. 文件「撤下」后仅撤回该文件归属；该文件在所有提交中都撤下时，对应复核成为孤儿判定并提示；
5. 归属中的贡献者未签 CLA → 进缺口，声明中该条目标注「CLA 待补签」，也可选择只导出已签署者；
6. 同一贡献者 × 同一文件只产生一条归属，并保留全部来源提交。

## 使用

```bash
npm install
npm run dev       # 本地开发
npm run build     # 类型检查 + 构建
npm run verify    # 运行判定引擎的 11 个场景测试
```

左下角可「载入示例」体验完整流程（含冲突、撤下、未签 CLA 场景），或导出/恢复 JSON 备份。归属声明在「归属声明」页预览并导出 Markdown。
